# 관제실 0.2.0 운영 배포 · 복귀 절차 (TC-DASH-006)

**감독의 최종 배포 승인 전에는 실행하지 않는다.** 이 문서와 `srv/docker-compose.yml` 변경은 준비물일 뿐이다.
운영 서버 경로·계정은 운영 폴더의 `.env` 에만 있고, 여기에는 쓰지 않는다.

## 0. 전제

- ② TC-QA 의 F1 재검증 PASS, 감독의 배포 승인.
- 배포 판: 브랜치 `work/20261110-houdini-dash-d1` 의 승인된 커밋 (앱 코드는 QA 검증본 `e36e545` 그대로). 판 이름을 `0.2.0` 으로 바꾸는 커밋은 `control/package.json` 한 줄만 바꾼다 — 배포 전 `git diff --stat` 로 그 한 파일뿐인지 확인한다.
- 기존 운영판 `0.1.6-rc.2-5dac91d` 이미지는 **지우지 않는다** (복귀용).
- 감독 원문 폴더는 만들지 않는다. compose 는 원문 폴더를 따로 마운트하지 않는다 — 따로 마운트하면 폴더가 없을 때 docker 가 호스트에 만들어 버리기 때문이다. 원문 대조 경로는 NAS 영상 폴더 마운트 안을 가리키기만 한다.
- nginx 는 바꾸지 않는다 (같은 `/Houdini/` 경로, 같은 8097 포트).

## 1. 새 입력 폴더 (모두 컨테이너에는 읽기 전용)

| `.env` 키 | 내용 | 준비 |
|---|---|---|
| `HPC_HANDOFF_HOST_DIR` | 인계 카드 폴더 (`TC-PROD/ TC-QA/ TC-WORK/ TC-DASH/`) | 이미 있음 (2026-11-10, 팀 카드 사용 중) |
| `HPC_DECISIONS_HOST_DIR` | 판정 기록 폴더 (④ 가 전사) | 배포 때 만든다. 스테이징 전사 기록 5건을 옮길지는 감독 결정 — 옮기면 모두 "원문 미확인"으로 표시됨 |
| `HPC_NAS_FILM_HOST_DIR` | NAS 영상 작업 폴더 | 있음 |
| `HPC_NAS_LAUNCH_HOST_DIR` | NAS 실행기 폴더 | 있음 |

컨테이너 사용자(uid 1000)는 폴더 소유자(서버 계정)와 다르다. 폴더는 `755`, 파일은 다른 사용자 읽기 권한이 있어야 한다. 앞으로 만들 판정 기록 폴더와 원문 폴더도 같다.
새 마운트 4개는 `create_host_path: false` 긴 문법이라, 값이 가리키는 폴더가 없으면 docker 가 빈 폴더를 만드는 대신 오류로 멈춘다(일회용 시험 프로젝트로 확인).

## 2. 배포 순서

```
0. 기록   배포 전 상태 저장: 이미지 해시·시작 시각·재시작 수, /·app.js 해시, 기존 API 6개 응답 키, compose·.env·media.json 해시
1. 빌드   docker build -t koprifossillab/houdini-control:0.2.0-<커밋7> control/     (기존 이미지는 그대로)
2. 백업   운영 폴더의 docker-compose.yml · .env 를 날짜 붙은 백업 폴더로 복사 (nginx 교훈: sites-enabled 같은 로드 경로에 두지 않음)
3. 변경   운영 폴더 compose 를 이 브랜치의 deploy/srv/docker-compose.yml 로 교체,
          .env 에 IMAGE_TAG=0.2.0-<커밋7> 과 §1 의 키 4개 추가
3a. 사전   §1 의 폴더 4개가 실제로 있는지, 권한이 755 이고 파일이 다른 사용자 읽기 가능한지 확인
          (판정 기록 폴더는 이때 만든다 · 원문 폴더는 만들지 않는다)
4. 확인   docker compose config 로 마운트 10개가 모두 read_only, 새 4개가 create_host_path false 인지 확인 (컨테이너는 아직 그대로)
5. 교체   docker compose up -d web          (재생성 수 초)
6. 점검   deploy/host/check-board.sh http://127.0.0.1:8097/Houdini   (CHECK_LEAK_TERMS 는 .env 의 가림 단어)
          + 포털 경유 /Houdini/ 데스크톱·휴대폰 화면 확인 + 30분 관찰
```

## 4. 즉시 복귀

**복귀 조건:** 점검 1–7 중 하나라도 실패, 500 오류, 기존 섹션 누락, 노출 발견, 메모리 초과, 감독·사용자 요청.

```
1. 백업한 docker-compose.yml · .env 를 운영 폴더로 되돌림   (IMAGE_TAG=0.1.6-rc.2-5dac91d, 새 마운트 없음)
2. docker compose up -d web
3. 확인: 이미지 해시 = sha256:5eb64b0d…  ·  / 응답 해시 = c7cc716e…  ·  app.js 해시 = 34c2814c…  ·  /api/board = 404
4. 감독 보고 (원인, 복귀 시각, 기록)
```

소요는 1분 안쪽이다. 기존 이미지가 남아 있으므로 빌드·다운로드가 필요 없다. 새 입력 폴더는 읽기 전용이었으므로 복귀 때 지울 것이 없다.
